## 打开方式与入口

开发服务运行时访问 `/template-lab/index.html`。打开即是当前聊天界面：侧栏问候、pin 行、名单，顶栏是所选猫猫，中间是原有的空对话（咖啡涂鸦、头像、「有什么事，直接说就行。」与起手句），底部是输入框。三只示例猫猫（宪宪、砚砚、墨墨）由原生种子模板按新建流程生成，名单里标「示例猫猫」。

| 要做的事 | 入口（与当前应用一致） |
| --- | --- |
| 新建猫猫 | 侧栏 pin 行末尾的 **+「新建」** → 菜单「新建猫猫」→ 选模板或从零开始。菜单里的「新建群组」只提示样页未包含 |
| 模板库 | 侧栏底部 **我 → 设置 → 模板**（原「人设卡」位置） |
| 本地 Agent 示例 | **我 → 设置 → 本地 Agent** |
| 查看某只猫的配置 | 点顶栏的猫猫名字，打开原有信息抽屉 |
| 样页主题、重置样页 | **我 → 设置 → 通用** |

手机宽度沿用原有的 ☰ 抽屉与遮罩，+ 在抽屉内；设置先显示项目列表，进入后顶栏可返回。设置里的其他项保持原顺序，只写一句「样页不加载」的说明。

页面只读取同目录的 `fixture.json`，不调用 clowder-bot 或 Clowder AI 的任何接口。状态只存在本标签页的 `sessionStorage` 键 `clowder-template-lab:v1`（主题选择另存 `clowder-template-lab:v1:theme`）；与第一版存档兼容，旧存档里的猫猫和模板修改会保留，只补上示例猫猫。应用自己的 `xbot-theme` 只读取、不写入。「设置 → 通用 → 重置样页」只清配置状态键 clowder-template-lab:v1，保留本页的主题选择；不会改动应用主题或真实数据。输入框可以打字，但发送按钮保持不可用，回车只提示聊天未接入，不会生成回复。

## 数据来源

`fixture.json` 的 `upstream` 段从 `upstream/clowder-ai/cat-template.json`（固定提交 `42017e0c`，文件 sha256 记录在 `provenance.upstream.sha256`）只读抽取，字符串逐字复制：全部 10 个 breed 与 20 个 variant，加上唯一没有对应 breed 的角色模板 `dsh`（小鲸鱼），合计 21 个原生种子。没有复制头像、配色、语音、mention、`accountRef`、`provider`、命令行参数等字段（清单见 `provenance.omitted`）。

`sample` 段是样页作者编写的示例：6 个 Agent 的名称、clowder-bot 适配状态、登录状态、默认模型与 effort 能力，以及上游 `clientId` 到 Agent 的映射。模型选项只取上游 `clientDefaults` 和各 variant 的 `defaultModel`；`claude-opus-5-5` 标为「示例覆盖」，不是上游默认，样页也不声称它在本机可用。effort 能力（Claude Code、Codex 有档位，Kimi 不支持，其余未确认）是演示三种状态的假设值。

## 设计决定

- **模板 = Agent + 模型 + 可选 effort + 画像**，另带猫种选择和「新猫名字建议」。模板名称、猫种、Agent、模型、画像在编辑页分区显示，列表按猫种分组。
- **种子**：每个上游 variant 一个模板，标出「上游默认」版本；`relationshipKey` 把 `opus-47`、`gpt-pro`、`gemini35` 并入同族。模板 ID（`tpl-s01`…）独立，不当作猫种。可编辑、复制、删除；编辑后标「已修改」并可「填回上游预设」；删除的种子留记录，可在列表底部恢复，不会自动回来。
- **版本与快照**：每次保存修订号加一。新建猫猫时复制当时的有效配置，只保留 `sourceTemplateId/Revision` 作来源。之后编辑或删除模板不改已建的猫；信息抽屉的「来源模板」列出与模板当前修订的差别，或注明来源已删除。
- **猫种**：自动模式只看模型系列（Claude → 布偶猫，GPT/Codex → 缅因猫，Gemini → 暹罗猫，GLM → 狸花猫，Kimi → 梵花猫），不看版本；无法判断时要求手动指定，不默认成布偶猫。孟加拉猫、金渐层种子保留显式身份。猫种 ID 用原生 `moonshot`，头像别名 `turkish-van` 只用于显示。创建时把解析出的猫种存进猫猫，之后不再随模型变化。
- **模型与 effort 是带标签的选择**：「跟随 Agent 默认」与「指定」分开存。effort 分有档位（不预选 max）、不支持（不传参数）、未确认（可填写，标待验证，不降档）。示例目录之外的模型一律视为 effort 未确认。
- **换 Agent / 换模型**：不兼容的模型和 effort 覆盖清成「跟随默认」并逐条说明，不换成邻近档位；自动猫种因此变化时也会提示。
- **新建流程**：第 1 步选模板（按猫种分组，可搜索）或「从零开始」；第 2 步自动填名字，显示配置摘要和能否创建，「自定义配置」默认收起，展开后逐项显示「已微调 / 恢复模板值」。未适配的 Agent 和云端 GPT Pro 席位可以保存在模板里，创建时说明原因并引导改用已适配的 Agent。新猫进入普通名单并被选中，桌面宽度下自动打开信息抽屉显示复制来的配置。
- **不暗示运行**：示例猫猫没有会话、消息或运行状态，不生成回复；抽屉里写明不会启动 Agent。唯一的样页标识是顶栏右侧的「样页 · 示例数据」小角标。没有密钥、供应商或登录界面。

## 评审路径

1. 打开页面，确认与当前聊天界面一致；点顶栏「宪宪」查看信息抽屉里的配置与来源。
2. 侧栏顶部 + → 新建猫猫 → 选「布偶猫 Sonnet」→ 名字自动填好 → 展开自定义配置改推理强度 → 创建；新猫出现在名单里并打开抽屉。
3. 我 → 设置 → 模板：打开同一模板换个模型并保存；回到抽屉看「来源模板」里的差别表；再删除该模板，确认猫猫配置不变。
4. 新建时选「暹罗猫」等未适配模板，看不可创建的原因；「从零开始」选 Kimi 后直接创建，看名字、猫种、职责的校验。
5. 我 → 设置 → 本地 Agent 看示例能力；设置 → 通用切换深色、重置样页；在手机宽度下检查 ☰ 抽屉、+ 和设置返回。

## 局限

- 示例 Agent、登录状态、默认模型与 effort 能力都不是实时检测；正式接入应改读原生 runtime 清单与 `runtime-models`，并由原生预检与创建。
- 设置里与模板无关的项只是占位；聊天、群组、分组、置顶切换等没有接入。
- 只做了单标签页内的修订检查；跨标签并发、幂等创建和原生规范化差异按契约草案留给正式实现。
- 现有「编辑资料」里的「导出模板 / 导入模板」指 Bot 资料 JSON，与这里的「模板」同名，正式接入时需统一命名。
- 样页没有改动 `client/index.html`、`app.js`、`persona-cards.js` 等生产文件。
