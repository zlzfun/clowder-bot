## 1．发资料，收成果

- **复用现有**：附件分支通过原生 `contextAttachments` 的 `workspace_file` 引用传递文件；Bot 保存文件清单与 SHA256 快照。发送、下载校验，会话切换防串线与发送幂等已做，不再新建项目／工作区流程。
- **已发现的缺口**：当前 `messageFiles()` 只展示能匹配 Bot 文件清单的 `context_attachment`；“存为交付物”主要由用户从目录手动收录，现有目录入口的请求不带 `sourceMessageId`。原生 `rich file` 或普通文件内容块尚不能因此自动成为 Bot 文件卡片。登记了 `sourceMessageId` 也不等于已经在那条消息中展示。
- **需构造案例的风险**：单聊 `transcript()` 对非过程猫消息，仅在有正文或清单内附件时保留投影。若原生消息只有文件块，可能被省略；需先构造合法原生消息验证，不能据此声称已复现用户文件丢失。接入成果时须覆盖无正文的文件回复。
- **上层适配可走的路径**：读取原生 `GET /api/threads/:threadId/artifacts` 和原消息的文件块，以 `threadId + sourceMessageId + publicationItem` 等原生坐标定位来源，接入现有成果展示。按原生规则区分发布成果、文件记录与版本；仅路径、文件存在或正文声称“完成”都不足以证明交付。
- **先验证的边界**：原生成果的 `/uploads/`、原生 API、外链与 Bot 本地快照是不同来源。现有 `NativeClient` 只处理 JSON，字节读取需受限适配；上游工作区下载要求合法 `worktreeId + path`，不能把 Bot 任意目录直接当作原生 worktree。没有合法读取来源时保留可解释的不可下载状态，不提供任意 URL／路径代理。
- **版本与失败**：成果聚合的 `workLineage`、使用 `view=works` 时返回的 `complete`，以及文件可下载性分别处理；局部可读不等于全量成功。无绑定版本的引用不能冒称原交付版本；收录当前内容应明确是新快照。上传成功但消息发送失败、成果发布但字节不可取，都保留已成功部分并允许重试。
- **验收场景**：用户发一份资料，请猫猫产出报告；猫猫通过已有原生文件发布能力返回结果，用户不找目录即可获取。另验同名不同版本、文件失效、发送结果未知后的重试、切换会话后的迟到响应。先跑通一个已支持的文件类型，不扩展到全部媒体和交互式页面。

**暂缓／上游需求**：若某类产出没有原生发布坐标、版本或授权读取路径，登记对应缺口；不通过扫目录、解析正文路径、注入新文件政策或增加另一套 Agent 工具协议补齐。

## 3．看得懂、少打扰的协作

| 要呈现的事实 | 使用的原生证据 | 不能据此推断 |
| --- | --- | --- |
| 哪只猫正在处理／消息在等候 | `/api/threads/:threadId/queue` 的 `activeInvocations`、队列；必要时核对 invocation 记录 | 安装了 CLI、Task 是 `doing`，不等于正在执行。 |
| 需要用户处理 | Approval Hub 的待处理项、Runtime Interaction 及其消息坐标 | 普通 `blocked` 任务不一定是在等用户。 |
| 当前由谁负责／交接是否生效 | Task 的 `ownerCatId`、`ownerRevision`、`lastAppliedHandoffMessageRef` 及关联原生消息 | `@`、请求已接收、负责人变化本身，不证明某次正式交接成功。 |
| 有新回复／某项任务完成 | 已持久化的回复、对应 Task 的 `done` 等明确终态 | 一次 invocation 结束、队列为空、某个子任务完成，不等于整件事完成。 |

- **复用现有**：Bot 已订阅原生任务、队列、消息、审批和交互事件，并有断线／事件缺口后的重读。隔壁已有任务与负责人展示；这轮增量不需要新建任务系统，也不以用户先建 Task 为前提。
- **先补的适配**：将上述事实按当前会话聚合；等待对象只有在原生记录明确时才说明。缺失证据或断线保持“暂时无法确认”，不能回落为“空闲／已完成”。保留并发事实，避免一条笼统状态掩盖另一项待确认操作。
- **提醒的真实缺口**：当前 `unread`、`completed_unread` 固定为 0；`transcript()` 读取即写入 `lastReadMessageId`。需区分数据读取与用户实际阅读，以会话为范围保存已读位置和提醒去重信息。这些属于展示元数据，不改变原生执行或任务终态。附件分支 `statuses()` 只返回 running／queued／idle，侧栏已有的 awaiting「等你确认」不能从这个接口得到状态，需要接入真实审批／交互记录。
- **最小提醒范围**：优先验证需要用户处理、可见的新结果及可采取行动的失败；普通工具调用与猫猫互相咨询不逐条提醒。同一原生事项重放／刷新不重复提醒，回到会话后对齐事实。首批只承诺应用内提醒，不附带关页推送或后台通知服务。
- **保留原生动作语义**：审批确认后仍读取原生回执；提交交接请求不显示“已交接”。首次范围不扩展 P004 的任务控制，不依赖 P006 的完整负责人历史；可以展示原生当前负责人和有证据的最近交接。
- **验收场景**：两只猫协作，其中一只需要确认；用户离开再返回，应找到准确待办与结果。另验一只完成另一只仍运行、咨询未交接、断线重连、重复事件、读取历史消息不清掉新结果提醒。

**暂缓／上游需求**：跨多次交接的完整审计、缺少原生记录的等待关系、任务级停止／恢复缺口另列上游需求；不能用 Bot 自存状态补造事实或默认套用整会话取消。

## 5．知道它记住了什么

- **先纠正范围**：`/xbot-api/bots/:name/memory` 目前转接 `/api/memory?threadId=…`，是当前会话共享便笺，不是该猫全部长期记忆。保留已有便笺和数据，不迁移成第二套长期记忆。附件分支群聊「记忆」页没有读取数据，却写着“对它说「记住……」就会出现在这里”；这条承诺应随入口收敛一并纠正。
- **第一步已有原生接口**：`GET /api/memory/profile` 读取用户画像；`GET /api/memory/taste` 读取偏好。两者均有按 ID／revision 读取详情和来源的接口，已在上游生产启动代码注册；Bot 当前白名单尚未开放这两组路径。优先适配这两类，不先把所有文档索引、人物资料和召回统计堆入入口。
- **读取必须保留语义**：展示原生内容、来源与实际范围；区分已保存、待确认、部分可读和暂时不可读。Profile／Taste 并非简单的“每猫私有记忆”；不得按当前猫名擅自改变归属，也不把 owner 私有资料注入群聊消息。
- **第二步逐类开放操作**：Profile 支持 `replace_content`、`hard_forget`；Taste 支持 `confirm_takeaway`、`correct`、`retire`、`hard_forget`。复用各自 `POST …/:memoryId/actions`，不造统一删除接口。按原生条目／文档粒度操作，不把画像全文伪装成可独立删除的一条偏好。
- **权限与并发**：原生要求 owner session、合法 Origin、CSRF；写入还要求 `requestId`、`expectedRevision`，遗忘要求 `confirmed: true`。现有 NativeClient 可承载会话与 CSRF，但新增路径仍需按方法收窄、实测 owner 范围；过期版本重新读取，不能默默覆盖。超时或多个操作部分成功时逐项核对回执，不批量宣布成功。
- **“记住／忘记”的实际含义**：自然语言请求通过已有聊天及原生提案流程处理；发出请求不等于已经保存。原生 `hard_forget` 的回执区分记忆删除、派生投影失效与原始来源保留，不应说成“从聊天和所有记录彻底抹除”。遵循每类返回的实际处理范围。
- **验收场景**：用户表达“以后先给结论”；先验证该部署能否经原生流程形成可见记录，再验证查看来源、修正及遗忘。用独立验收数据覆盖待确认、没有记录、无权限、部分读取失败、revision 冲突和重复提交，不修改用户真实记忆。

**暂缓／上游需求**：没有通用“所有记忆一键清空”的承诺，不增加 Bot 自动归纳／写入／检索／注入循环。某类自然语言请求或生命周期操作无法由既有契约完成时，保留原生可用入口并登记具体缺口。

## 实施前的最小验证包

1. **成果**：在附件分支基线上验证“原生发布 → 有来源的展示 → 授权下载”，保留现有快照和旧文件；确认不需要 P007 才能完成这条路径。
2. **协作**：验证仅用未修改上游事实即可得到正确的当前状态，再补已读／去重；不以 P004／P006 的新增字段作为必需输入。
3. **记忆**：用独立实例验证 Profile／Taste 读取、owner 权限和部分失败，再决定第一种写操作；不直接对当前用户数据试删。
4. **交互**：以上最小方案已由本机 `claude-opus-5-5 --effort xhigh` 只读探索。进入实施后，前端改动仍由本机指定模型完成；验证多项并发不被收起后遗漏、原生结果正确定位、记忆读取失败不伪装为空，并保留现有文件／历史对话流程与样式。
