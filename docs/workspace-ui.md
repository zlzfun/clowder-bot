# 文件、历史对话与聊天任务前端规范

适用于输入框附件、消息里的文件卡片、信息抽屉的「文件」页、猫猫「详情」页的「历史对话」、「任务」页顶部的任务卡，以及输入框上方的任务条。实现位于 `client/public/workspace.js`（DOM 与请求）、`workspace-rules.js`（无 DOM 的规则）、`workspace.css`；后台执行语义复用运行面板的 `runtime-tasks.js`（`window.ClowderTasks`）。服务端语义见 [项目、文件与聊天任务](workspaces.md) 与 [默认文件目录与原生协作](default-files.md)；前端行为测试在 `tests/workspace-ui.test.ts`。

2026-11-05 精简（用户批准）：保留附件与交付物；负责人与传球由 Clowder AI 原生 Task 决定，前端不另设负责体系、咨询或转交模式；项目与工作区管理收起，使用自动默认目录。下文是精简后的现状。

2026-11-05 聊天体验 1、3、5：原生文件视图接入同一套卡片（「成果」、可用性、局部失败）；输入框上方的执行行与任务条在 `GET <scope>/activity` 可用时合并为一行状态（`chat-experience.js`，见下文「状态行与已读」）；「记忆」页见下文「记忆」。接口以 [聊天体验适配契约](chat-experience-api.md) 为准。

## 入口与布局

- 顶栏：只有原有的身份按钮。没有项目或工作区按钮、菜单，也没有「新建项目」。
- 新建群组：原版的「名字 + 成员」表单，请求体只有 `name`、`members`。
- 输入框：`plus` 列的回形针按钮打开系统文件选择（可多选）；粘贴、拖入任意文件都成为附件，粘贴文件时不再把文件名当文本贴进去。待发送附件是小卡片：图块（图片显示缩略图，其余显示扩展名）、名称、状态（等待上传 / 上传中… / 大小 / 没传上去：原因）、重新上传（失败时）和移除。
- 消息：单聊和群聊的用户、猫猫消息都按 `attachments` 显示文件卡片，用户侧靠右；只有附件的消息不再画空气泡。一条猫猫消息拆成几个气泡时，文件只挂在最后一个下面。猫猫回复 `SILENT`（没什么要说）时从不显示这个词：没有任何文件或图片的才整条不画（单聊、群聊、例程相同，群聊预览也跳过）；带文件或图片的保留卡片／图库，只是不写正文。
- 抽屉：标签页为「详情、记忆、任务、文件、轨迹、上下文」。窄于 960px 时标签间距略收紧；仍放不下时可横向滚动（不显示滚动条）。
  - 「文件」：服务端读出原生记录时先有「成果 · N」（猫猫在对话里发出的原生成果），再是「交付物 · N」与「附件 · N」两组文件卡片（附件超过 6 个时可展开全部）；「刷新文件」在第一组的标题上。下面是默认收起的「更多文件」。首屏不出现路径、工作区卡片或目录切换，也不读取目录。展开后才读取并显示：工作目录路径（末三段，悬停显示全路径，可复制）、目录浏览（面包屑，文件夹逐层进入，文件行有大小和「存为交付物」）。只有旧项目会话的共享目录与工作目录不同时，展开区里才有「工作目录 / 共享目录」切换。
  - 「详情」（猫猫）：在原有小节之后，猫猫已知的对话多于一个时才出现默认收起的「历史对话 · N」。每行是对话标题和「开始于 时间」，当前对话标「当前对话」且不是按钮。旧项目会话的标题可能是原项目名，但没有任何项目管理操作。群组没有这一项。
  - 「任务」：顶部「任务 · N」（只有「刷新任务」），未完成的任务卡在前，已完成的收进「已完成 · N」；下面是原来的子代理执行与猫猫的定时任务，前加小标题「执行与定时任务」（「定时任务」一节由 `schedules.js` 挂在执行各小节之后，见 [xbot-frontend.md](xbot-frontend.md) 第 16 项）。群组的「任务」页只有任务卡。没有「新建任务」「指派」「改派」。
- 任务条：有未完成任务时，输入框上方（`#work-status` 之后）一行「任务 N · 进行中 a · 受阻 b · 待办 c」加负责人的小头像，点击打开抽屉的「任务」页并把焦点放在标题上。`GET <scope>/activity` 可用时，它与执行行一起由状态行取代（`.dock.cx-on`），只在接口不存在（404）时出现。

## 文案约束

- 主界面只说「文件」；「工作目录」「共享目录」和路径只出现在展开的「更多文件」里。不显示文件策略、只读或保护标记：服务端没有明确报告的保护，前端不作声明。
- 任务卡：标题与普通进度标签；「负责人 + 头像 + 名字」，没有时「还没有负责人」，名字只取自读到的 Task；后台执行只在有记录时显示一行（「后台执行：运行中 · 时间」，历史记录写「上次后台执行：…（不是当前执行）」），没有记录不写「空闲」。
- 传球只说「请求传球」：按钮「请求传球…」，表单「传给」「说明（可选）」与提示「会请「A」按原生流程传球；传球完成前，负责人不变。」，提交「请求传球」；成功后「已请求传球。负责人仍是「A」，传球完成后这里会更新。」，卡片另记「已请「A」传球给「B」（时间）。负责人以任务记录为准。」。不出现「已传球」「已交接」。回执在负责版本变化后或 30 分钟后消失。
- 关于负责人的卡片提示只在说它时的负责版本（`ownerRevision`）上成立：读到别的版本后，回执与这句一起撤下，改为只陈述记录的「负责人已更新，现在是「C」。」（无负责时「现在没有负责人」），不说是哪次请求造成的。传球请求的 202 晚于已读到的新版本时，说「传球请求已提交。负责人已有变化，以任务记录为准。」，不记回执。
- 「流转记录」只列原生 `assignmentHistory`，新的在前：时间、「A → B」（空为「无负责人」）、方式、版本号、是否来自聊天消息。方式彼此区分：`handoff`「传球」、`human_update`「手动指派」、`claim`「认领」，未知值写「负责人变更」。没有记录时写「还没有流转记录。之前的变更不会补记。」；运行时没开启记录（`historyAvailable` 为假）时写「当前运行时没有开启流转记录。」。
- 停止请求写「停止请求已提交，实际状态以执行记录为准。」；撤销、停止标记注明「这不代表已在进行的工作已经停止」；恢复写「已解除禁止。这不会自动重新开始执行；需要继续时，在聊天里请负责人继续。」，在原生确认执行结束前「允许继续 / 恢复任务」不可用。
- 没有任务时写「还没有任务。直接在聊天里说要做的事就好，不用先建任务。」。界面从不替用户发起执行。
- 文件取不到时卡片原位说明：「文件已不存在」「文件内容已变化，不能按原样下载」，并停用下载与预览；暂时读不到时只说「暂时读不到这个文件」。交付物是快照：「会保存一份带校验的快照，之后改动不影响它」，再次保存按钮写「再存一份」。
- 原生文件视图（`nativeSource:true`）是猫猫的原生成果或附件，不是快照：交付类写「成果」，从不写「交付物」「快照」；`size:null` 不写大小（不写 0 B）。`availability` 不是 `available` 时，卡片写服务端的 `unavailableReason`（没有时「这份成果暂时不能下载」「这个文件暂时不能下载」），下载与预览停用，图片不请求；下载时服务端 404／409／403 的中文原因原样显示。原生记录读不到（`nativeReadStatus:'unavailable'`）时，「成果」写「猫猫在对话里发出的文件暂时读不到。下面只显示已保存的文件。」（读到一部分时写「还有些猫猫发出的文件暂时读不到，这里可能不全。」并列出读到的）加「重试」，服务端原因放在提示里，「成果」不显示数量，「附件」的空状态写「已保存的附件里还没有文件。对话里的其他文件暂时读不到。」；服务端没有这个字段时不显示「成果」一节。
- 加载、空、错误状态都是短句中文：「正在读取…」「这个文件夹是空的。」「没能读取：原因。」加「重试」；后端没有接口时写「当前后端还没有开放……」或不显示该入口，不显示示例数据。服务端的中文原因原样显示，英文错误码换成中文说明。

## 交互与一致性

- 附件绑定线程：文件在加入时上传到当前会话的确切原生线程（`expectedThreadId` 取自最近一次聊天记录或工作目录读取）；还不知道线程时先显示「等待上传」，10 秒仍不知道则标为失败、可重试。每批文件依次上传。一条消息最多 8 个、每个不超过 20 MB、不收空文件或文件夹，超出的写明原因而不加入。
- 切换会话、切换历史对话或线程变化（例如在别处开了新对话）都会中止进行中的上传、清空待发送附件；迟到的上传结果不会落进另一个会话。切换历史对话的请求进行中，回形针停用，粘贴或拖入的文件不加入，并提示「正在切换对话，切换好后再添加附件。」。
- 发送：文字和已就绪的附件一起发出，附件随请求带 `attachments`、`expectedThreadId`；每条消息都带 `idempotencyKey`。没有发出去时文字照旧放回输入框，附件也放回（同一会话、同一线程时），失败行写「没发出去：服务端原因，原文还在输入框里，附件已放回」；发送失败时已切到别的会话的，附件留到回到该会话且线程未变时再放回（30 分钟内）。结果未知（无应答或 5xx）时重发同样的文字和附件沿用同一个幂等键；明确被拒绝（4xx）时换新键。409 之后会重新读取会话。
- 历史对话：打开页面时当前对话不变。点一行即请求 `PUT /xbot-api/bots/:name/conversation {threadId, expectedThreadId}`，`expectedThreadId` 是页面已确认的线程（确认弹层期间线程变了，取变化后的）；只在服务端已知的线程间切换，从不新建项目或线程。有待发送附件时先确认它们会被移除；发送进行中不切换；一次只切一个。成功后提示「已切换到「标题」」并重新打开这只猫的对话；若应答到达前聊天记录已显示该线程，不再重新打开。被拒绝（源或目标在执行或排队、线程已变化、不属于这只猫）时留在原对话，在折叠区原位显示服务端原因，并重新读取列表和工作目录。切到别的会话后迟到的应答不生效。
- 刷新：没有独立轮询器。每次聊天记录读取（3 秒轮询、原生 SSE 事件触发的读取）通知模块；聊天记录有变化、原生事件到达，或距上次读取超过 15 秒（「任务」页打开时 4 秒）才重新读取任务；「文件」页打开时随记录变化和原生事件刷新文件列表。读取到的线程与当前不同会清空并重读，5 秒内反复横跳的读取只采纳不重读。历史对话列表在首次绘制、线程变化、展开折叠时读取；同一线程的轮询和重绘不重读，也不动附件。
- 防过期：每次切换会话都有新的代次，每类读取有自己的请求序号；旧会话或旧请求的应答一律丢弃（历史对话列表只采纳最新一次读取）。停止 / 撤销 / 恢复与传球的应答若比已读到的同一 Task 旧（`ownerRevision` 更小，或相同但 `updatedAt` 更早），保留已读到的记录，由随后的常规读取对齐；传球失败后的重试沿用同一幂等键。抽屉重绘时，模块的页面保留原节点（文件夹位置、展开的折叠与表单、输入中的说明和焦点都不丢）；「详情」每次重建时历史对话是同一节点，重建前在其中的焦点会回到原处，除非用户已点到别处或移开焦点。任务卡按 ID 复用，刷新只改变化的部分。
- 键盘与焦点：弹层内 Escape、Tab 循环、其他按键都不冒泡，关闭后回到打开它的按钮（按钮已被重绘替换时回到输入框）；任务卡里的表单 Escape 关闭并回到触发按钮；移除附件后焦点到相邻附件或输入框；进入文件夹后焦点到面包屑的当前位置；切换历史对话后焦点落在现在打开的那一行。停止和撤销需要在 3 秒内再点一次。

## 状态行与已读

- 一行：行首是最紧要的一类，顺序为待确认、失败、处理中、排队、未完成任务；其余类别写成「· 处理中 1 · 排队 1 · 任务 3」，不因优先级隐去。多项待确认写「N 项等你确认」。读取部分失败追加「· 部分状态读不到」；没有任何事项而读取不完整、或第一次读取就失败时写「暂时无法确认状态」；读取失败但有上次结果时保留并注明。只有服务端 `unread>0` 且最新回复不在视野内时才写「N 条新回复」。不用「子代理」等内部概念；执行结束不称回复，Task 完成只描述该任务。
- 点击原位展开：默认列前 6 项；更多时其后有「查看其余 N 项」，原位列出全部待确认与并发事项（原生顺序），再点「收起」回到前 6 项。展开与否在同一会话的刷新、重绘中保持（焦点留在这个按钮上），换会话或线程后恢复简短。服务端计数多于列出项时另写「另有 N 项没有列出」。每项是类别、猫头像与原生标签。有 `messageId` 的「查看」在当前对话里定位并聚焦该消息；任务项（有 `taskId`，即使也带来源消息）的「打开任务」打开「任务」页并聚焦该卡片（已完成的会展开「已完成」）；找不到时原位说明，不猜测。待确认另有「去确认」，在新标签打开运行面板，用其原有审批控件；聊天里不批准、不自动批准。Escape 收起并回到这一行。
- 侧栏：猫与群的第二行显示「N 项等你确认」「有一项失败」「暂时无法确认状态」，群也显示处理中／排队与红点；点击先打开该会话，再按消息坐标定位，没有坐标时展开状态行列表。
- 已读：只有页面可见、对话区未被遮住、activity 与当前对话是同一线程、有未读、`latestMessageId` 那一行在对话视口里停留 0.8 秒，才 `POST <scope>/read`；同一条只发一次，一次一个请求。404（这条不是该线程的可见回复或已不存在，不当作接口缺失）与 409（线程已变化，另重新读取状态）只针对这一条回复，之后的新回复照常确认；其他失败 20 秒后才再试。切换会话或线程后到达的应答不改当前会话：成功只记下那一条已确认（不改红点和状态），失败不留下拒绝记录、等待或重读，回到原线程时那一条仍会再确认。后台轮询、隐藏页面、停在旧消息时都不确认。只做应用内提醒，没有系统通知。

## 记忆

整个「记忆」入口只读：不提供任何写操作（编辑、确认、停用、遗忘、添加、删除）。

- 单聊「记忆」页：默认收起的「关于你」「你的偏好」，展开才读取；条目按原生内容原样显示，`pendingCount` 只写「另有 N 条待确认的修改，确认前不算已保存，也不在上面的内容里」，停用条目排后并标注。失败、没有权限、部分可读、暂时读不到、接口未开放与真的为空各有说法，失败从不显示为「还没有」。每条「来源」展开才带 `revision` 读取；409 提示「这条已经更新，重新读取后再看来源」。没有任何编辑、确认、停用或遗忘按钮。
- 「这个对话的便笺」：原会话便笺，与原便笺界面一样只读，没有输入框、添加或删除。抽屉自带便笺时直接显示；没带时 `GET` 读取一次，失败写「便笺没能读取：原因。这不代表没有便笺。」加「重试」（再次失败时焦点留在「重试」，抽屉重绘不自动重读），读到为空才写「这个对话还没有便笺。」。提示「便笺只属于这个对话，换到别的对话不会带过去。」
- 群聊「记忆」页只写「群聊没有可查看的记忆。关于你的资料和偏好，在和猫猫的单聊里查看。」，不读取 owner 资料，也不承诺「说记住就会出现」。

## 用到的接口

`GET <scope>/activity`、`POST <scope>/read`、`GET /xbot-api/bots/status`（`thread_id`、`activity`、`groups`）、`GET /xbot-api/memory/profile|taste`、`GET /xbot-api/memory/:kind/:id/source?revision=…`、`GET /xbot-api/bots/:name/memory`（便笺，只读；服务端原有的 `POST`／`DELETE` 路由保留，前端不调用）；`GET <scope>/workspace`（只用 `threadId`、`workspacePath`、`sharedPath`；`defaultRoot`、`filePolicy` 等字段不显示、不据此声明）；`GET /xbot-api/bots/:name/conversations`、`PUT /xbot-api/bots/:name/conversation`；`GET/POST <scope>/files`、`GET <scope>/workspace-tree`、`POST <scope>/deliverables`；`GET /xbot-api/files/:id/download`（含 HEAD 探测）、`/preview`、`/image`；`GET <scope>/tasks`、`POST <scope>/tasks/:id/handoff`、`POST <scope>/tasks/:id/control`；既有的 `POST <scope>/messages` 与 `POST /xbot-api/groups`。`<scope>` 为 `/xbot-api/bots/:name` 或 `/xbot-api/groups/:id`。下载链接、图片地址都按文件 ID 自行拼出，不直接使用服务端返回的 URL。前端不再调用 `/xbot-api/projects`、`PUT <scope>/workspace`、`POST <scope>/tasks` 与 `PATCH <scope>/tasks/:id`（服务端兼容接口另行保留或退役）。

## 已知限制

- 只能浏览当前会话的工作目录（旧项目会话另有共享目录）；工作目录里的文件本身不能预览，只有存成交付物或作为附件后才能下载、预览。
- 文件卡片只在消息有 `attachments` 时出现；旧的 `images` 图片仍按原来的图库显示。附件上传没有进度百分比，只显示「上传中…」。
- 非普通 Task（`kind` 不是 `work` 或带 `subjectKey`、`entrustedWork`）在聊天里只读，提示到运行面板处理。任务状态与负责人不在聊天里修改；没有负责人的 Task 等原生认领。
- 历史对话只列服务端返回的对话，没有重命名、删除或新建入口；列表读取失败时保留上次结果、首次失败不显示该项。
- 已上传但最终没有发送、或被移除的附件，服务端仍保留记录（目前没有删除接口）。
- 已读只按服务端的 `latestMessageId` 确认：如果那条回复在聊天里没有画出（例如被过滤），这条未读不会被前端清掉。消息定位只在当前读到的最近 200 条里找。
