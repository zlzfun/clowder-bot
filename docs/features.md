# 特性与上游的关系

每个特性现在靠什么实现、上游走到了哪一步、接下来该怎么办，都在这一份里。基线：引擎固定在上游 `next` 分支的 `fe632f8f`，2026-11-28 核对。

「上游」一栏是读上游源码和它的特性文档得出的，**没有运行验证**；写着「待实测」的，动手之前要先在隔离运行时上确认。逐条依据在 [上游现状核对（2026-11-28）](history/upstream-status-20261128.md)，表里方括号中的数字是它的条目号。固定提交每换一次，这一栏要重看。

## 怎么读

每一行有两个状态。

**现在**：这个特性今天是怎么来的。

| 写法 | 意思 |
| --- | --- |
| 原生 | 用的是固定版本、未打补丁的上游能力，Bot 只做适配和展示 |
| 补丁 | 走上游的机制，但其中一块由本地补丁提供。补丁是历史债务，不再扩大 |
| 暂代 | 上游没有，Bot 层先用组合、推导或绕行顶着；这件事本该由上游来做 |
| 自有 | 只是界面或这台电脑上的事，和引擎无关 |
| 没做 | 还没有 |

**上游**：我们要的那一块，上游现在的情况。已有（固定版本的源码里有）、在做（特性文档标着进行中）、有规划（只有规格或想法）、未见（搜过文档和源码，没有）、不做（上游写明不做，或已经下线）。

两栏合起来，就是这个项目特有的几种处境：

| 现在 | 上游 | 处境 | 该做的 |
| --- | --- | --- | --- |
| 原生 | 已有 | 已经依赖上游 | 保持；换固定提交时复核 |
| 补丁 | 未见、有规划 | 靠补丁撑着 | 不扩大使用面；把退出条件提给上游；上游有了就退补丁 |
| 暂代 | 未见、有规划、在做 | 暂时这么做，最好由上游实现 | 等上游实现后改为依赖上游；在那之前不给暂代的做法加码 |
| 暂代 | 已有 | 上游已经有了，我们还在用自己的 | 实测，然后换成原生 |
| 没做 | 已有 | 上游有，Bot 没接 | 想做的时候在适配层接上 |
| 没做 | 在做、有规划 | 上游在路上 | 等上游实现再依赖，不在 Bot 层先做一套 |
| 没做 | 未见、不做 | 上游没有这个方向 | 先看能不能用已有的原生操作组合出来；不能就提需求，或者放下 |

## 一、先看这些

表太长，值得先知道的是四组。细节在后面各节。

**上游已经有了，可以把暂代的换掉**（都要先实测）

- 未读与已读：上游有按对话的已读位置和未读数 [21]，我们还在用自己存的那一份。
- 搜索：上游的消息检索有词法模式，没有嵌入模型时自动降级 [24]；「原生检索返回空」是 2026-11-11 在旧固定版本上的结论。
- 应用为什么不走插件包：当时的判断是插件带的 MCP 到不了猫；上游在我们这种部署下其实有条件地生效 [10]，这条前提要重核。
- 后台委派的提示词（补丁 P002）：上游有受支持的追加途径 [16]，能不能据此退掉补丁要评估。

**上游已经有了，Bot 还没接**

在对话里回答猫的提问 [29]、记忆的纠正与忘记 [30]、改提醒的内容 [32]、图集、音频和 HTML 小组件三种内容 [28]、更多 Agent（DSH、OpenCode、Pi、通用 ACP）[33]、事项记忆、缓存冷热、主人昵称 [31]。见第五节。

**暂代着或靠补丁撑着，上游还没有**

表情回应、群聊成员准入、群里回复定向、这台电脑的四处、应用的两处绕行、定时列表、任务控制、模板库。它们对应第四节的 U-01 至 U-22。

**上游不做，或者方向相反**

- 桌面操作的逐步审批：上游的通用授权已经下线，写明不接进审批中心 [5]。「等上游来做按动作审批」这个前提不成立了；2026-11-28 定为接受现状，不在 Bot 层另做一套（[计划与待办](backlog.md) 第六节）。
- 引擎自发消息（重启和睡眠后的接续、掉球检查）的开关：上游写明不加 [38]。
- Gemini CLI 和 Antigravity 两种运行时在上游已经退役 [33]。孟加拉猫的模板用的就是 Antigravity，按原样接上的路没有了；暹罗猫（Gemini）对应的是上游还在做的 AGY。

## 六、怎么维护这张表

- 做完一个特性：在第二节加一行或改一行，写清「现在」是哪一种；用到的上游能力写接口或特性编号。
- 新加了绕行或暂代：在第二节标「暂代」，在第四节加一条 U，写清换回原生的条件。不新增补丁。
- 换固定提交之后：按第三、四节逐条重看上游有没有变；「暂代而上游已有」的优先处理；另写一份带日期的核对放进 [history/](history/)。
- 这里只写关系和下一步。怎么做的细节写在各自的接口文档，没做完的事写在 [计划与待办](backlog.md)。
